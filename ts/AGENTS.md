# TypeScript test scope and cost

- For valid observable Tao behavior, use authored Tao journeys as the primary proof under root `AGENTS.md`. Before adding a package test, find the existing journey assertions and name the distinct behavior they cannot credibly prove. Executing a layer is not proof of every branch, but do not recheck the same asserted outcome at each layer.
- Permit package tests only for an essential basic contract, demonstrated regression or important precise edge with that coverage gap. Diagnostics, formatting/idempotence, generated TypeScript types, editor navigation, scheduling/work counts and external-boundary integration can justify gaps; being in a package does not itself justify another test. Keep each exception focused rather than building an exhaustive matrix.
- A named regression is not a permanent exemption from consolidation: retire its package test when a surviving journey credibly detects the same bug. Assertions on internal representation or generated spelling need an independently required contract; preserve behavior, not incidental implementation choices.
- Keep Tao decisions and transformations real. Exercise existing production boundaries with recording executors, isolated tools, controlled clocks or schedulers, and explicit event acknowledgements. Do not wait for arbitrary elapsed time to prove policy, ordering or absence; bounded waits for actual external readiness may retain failure timeouts.
- Real browser, process, filesystem, Git or installation work must prove behavior that a cheaper controlled boundary cannot. Retain a small representative integration proof for each required boundary; put policy permutations in focused controlled tests. Do not replace a real boundary with a mock and claim its acceptance coverage survived.
- Treat runtime as part of test design. Investigate slow-test warnings for new or materially changed tests; simplify the work or record the required contract, why a cheaper proof is insufficient, measured cost and intended invocation in task evidence. A large failure timeout is not itself a slow execution.
- Assess cost per logical subject across cases and files, including setup, teardown, subprocesses and repeated fixtures, as well as whole-run wall time. Splitting, renaming, raising warning thresholds or moving setup into hooks does not resolve excessive cost. Numerical hard budgets require calibrated automation; current warnings are not enforced limits.
- Search `@shared-tests` testing helpers before adding another harness. Use `test-quality` for proof ownership and retirement, and `verification-lanes` for choosing checks. Fast overlapping Tao journeys need no deduplication solely for sharing a code path.
