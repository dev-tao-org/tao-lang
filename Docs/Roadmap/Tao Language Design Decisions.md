# Tao Language Design Decisions

This index records agreed design across the server-side and typed-calculation design discussions. The [runtime PoC](Tao%20Runtime%20PoC.md) tracks implementation and verification.

## Package addressing and manifest ownership

- Tao source projects are distributed by making them available at a supported source address, such as GitHub; no project publication block gates Tao consumption. Package visibility owns that API. A `ts-library` declaration owns one publication block selecting a generated TypeScript API. Distribution/install lifecycle for that generated artifact remains to be designed separately from Tao source distribution.
- Imports name individual declarations. Publication selects individual declarations or actual `@name` project packages. The [TypeScript library specification](../Specification/TypeScript%20Libraries.md) describes the generated API.
- Visibility has three levels: `file` (default), `folder`, and `package`. Package-visible declarations form the addressable API, including for consumers outside the project through its source address. Bare imports search the same folder. Relative imports select folders within the same package. Package imports preserve subfolder paths; see [Projects and Dependencies](../Specification/Projects%20and%20Dependencies.md).
- `@name` folders establish local package boundaries without mandatory package declarations. Bare `@name/subpath` addresses only the current project's packages, under ordinary visibility. External requirements use explicit source providers and aliases.
- Packages have no separately declared name: external Tao addressing combines the project source with the package's `@folder` name, independent of its location within the project. This supersedes the proposed declared package-identity field. Tao projects do not publish to or install from npm; consuming `npm:` dependencies remains supported.
- Tao-managed package manifests are derived idempotently from Tao declarations and locked dependencies. Provider and sidecar requirements remain owned by their packages; consumers do not repeat transitive requirements.
- Published top-level TypeScript declarations use named root exports with one public address each and no publication aliases. Ordinary TS-library consumers require no lifecycle API: one automatically initialized library scope owns singular top-level state; view-local state remains per mount. Tao generates local `@package` mappings for TypeScript as well as Tao consumers; see [TypeScript Libraries](../Specification/TypeScript%20Libraries.md).
- Implementation remains pending package-block ownership and metadata design. Local cross-project checkout linking is explicitly deferred until post-MVP; it is not a prerequisite for same-project imports or generated manifests. See [Projects and Dependencies](../Specification/Projects%20and%20Dependencies.md).

## Data and provider boundaries

- Author provider-neutral entities with singular/plural declarations. App or datasource configuration selects the provider, which assigns entity IDs. Import external actions explicitly.
- Entity access and validation, transaction semantics and authored revision checks are specified in [Data Access and Validation](../Specification/Data%20Access%20and%20Validation.md).
- Provider capabilities must satisfy the program's requirements. Matching rejects unsupported guarantees. Adapters implement the generated SDK callback transaction boundary and prove its guarantees through [provider conformance](Tao%20Provider%20Conformance.md). Providers own synchronization and queueing.
- Managed deployment uses provider-neutral `tao ship`, compiler-owned app definitions and provider planning/application of schema and access rules. Private Notes on self-hosted InstantDB precedes Firebase/Firestore and Convex deployment integrations. See the [deployment contract](Tao%20Provider%20Conformance.md#managed-deployment-contract) and [paused implementation review points](Tao%20Runtime%20PoC.md#managed-deployment-review-points).

## State and actions

- The generated helper is `sidecar.implement`. Action implementations may return immediately or via promises; pure functions remain synchronous. Standard decoding/return-contract/host failures are implicit and documented; explicit domain failures are separately declared.
- Each Tao file may have one matching-name sidecar. Sidecars may import ordinary private TypeScript helper modules under their managed execution boundary. Exact sidecar naming and possible omission of its pathname are deferred.
- For now all apps run with dev mode enabled. A two-finger double-tap opens a developer overlay with render-tree bounds, state export for Studio, on-screen edit mode and event/failure inspection. See [App Developer Overlay](App%20Developer%20Overlay.md). Structured issue metadata remains available to app logic.
- All sidecar execution, including additional async work and callbacks, belongs to Tao-managed execution through generated contracts and supported helpers. Preserve typed failures, normalize unexpected host exceptions and support explicit domain-error translation. Validate returned values with trusted immutable-value fast paths. Pure sidecars may mutate private construction buffers without mutating inputs or published outputs.
- Values expose `encode()` for their external JavaScript representation, separately from JSON serialization. Checked `Type.from(input)` construction raises typed Tao failures for invalid input, without class-constructor syntax. Each sidecar default-exports an implementation object through `sidecar.implement` imported from its owning Tao module. This supersedes the top-level `ImplementSidecar` export. The concrete helper signature supplies TypeScript contextual typing and editor completion without manual generic arguments.
- Import generated sidecar types, factories and implementation contracts from their owning `.tao` module. Keep pure callback contracts distinct from action callback contracts.
- Ordinary view-sidecar parameters receive read-only reactive readers by default. `state` adds write authority; immutable arguments also satisfy the read/observe contract. Function and action input contracts are separate.
- Writable sidecar parameters use `Value state text`, replacing legacy `mutable`. They bind caller-owned writable storage, including draft fields. `draft Item` constructs detached data; explicit `state Draft = draft Item` owns its retained writable storage.
- Sidecar requirements are owned by Tao declarations and compiler-generated interfaces/signatures. Reuse ordinary language concepts; opaque requirements may use sidecar-only declaration syntax when necessary rather than hidden TypeScript metadata.
- Authored Tao and generated code use three-space indentation; handwritten repository TypeScript follows its two-space policy. Runtime operations own language semantics; generated code connects them rather than duplicating evaluation logic.
- [Local State and Data Drafts](../Specification/Local%20State%20and%20Data%20Drafts.md) owns state replacement, detached edits and opt-in persistence. Automatic persistence-key shorthand follows explicit stable keys.
- Drafts track per-field baselines, follow live changes in untouched fields and submit captured changed-field patches. Conflict selection preserves unrelated edits; confirmed creation binds the provider entity while preserving newer edits. Local acceptance is distinct from authoritative confirmation; its public inspection API remains open.
- [Actions and Results](../Specification/Actions%20and%20Results.md) owns activity inspection, failure presentation, guards and disabled interaction. [Advanced Action Execution](Advanced%20Action%20Execution.md) owns the deferred retry design and its remaining questions.
- Keep `first` and `last` consistent across lists. Collection insertion uses `add Items << Item` to append and `add Item >> Items` to prepend. MVP action inspection is direct aggregate matching: `when ACTION` matches all applicable cases, while render `pick ACTION` selects the first matching branch in source order with an available `otherwise` fallback. Prior listable status, handle and invocation-selection designs are retained in the post-MVP document.
- Use spaces inside interpolation braces, as in `{ Expression }`. Prefer a declared type name as its binding name and use an alias to distinguish roles. Use lowercase core type names.

## Typed calculations

- Reject incompatible loaded definitions of the same nominal declaration rather than using structural compatibility. Plain external values are decoded normally; opaque host objects require explicit conversion, not automatic getter/property inspection. Sidecar network/storage effects belong inside invoked actions, not module loading; initialization exceptions still receive Tao handling.
- Authored Tao declarations use uppercase names; compiler/SDK-defined imports use lowercase names, avoiding the proposed `$` namespace prefix. Core value constructors use text/number/boolean. SDK arithmetic initially requires explicit wrapped operands; implicit core-literal wrapping may be reconsidered later.
- Core text/number/boolean values also use SDK snapshot wrappers, with explicit extraction to JavaScript. Encoding recursively converts ordinary records/lists and raises a typed failure for unsupported values. Type.from rejects unrelated already-typed nominal inputs rather than automatically unwrapping; explicit extraction then checked construction is permitted. Ancestor/descendant rules remain separate.
- Checked record construction rejects undeclared fields. Collect multiple validation issues within a bounded diagnostic budget, with field paths. Retain the full rejected payload on the failure, without truncation, and expose full-payload inspection only through failure debug `Render`, using useful context and best-effort expandable value presentation. Default error messages, UI and logs omit rejected values.
- Nominal equality compares stable declaration identity and contained value. Separate loaded copies of the same compiled declaration share identity; distinct declarations do not become equal merely because payloads match. Generated pure callbacks use named argument objects.
- Expose Tao equality and corresponding language-defined value operations through the Tao TypeScript SDK so consumers share Tao semantics rather than implementing separate comparisons with JavaScript operators. Exact API names remain open.
- Generated TypeScript nominal values are immutable and retain runtime type identity. Outputs preserve declared named Tao types, with explicit primitive extraction. External data enters through generated checked decoding that rejects invalid input without silent coercion.
- Callbacks supplied to pure sidecars are callable only during their owning evaluation; runtime wrappers enforce this lifetime. View/action callbacks have separate contracts.
- Reactive dependency tracking follows actual reads, including conditional branches, and refreshes the dependency set on each evaluation. Inactive branch inputs do not trigger recomputation.
- Compiler/runtime-managed wrappers own reactive evaluation around pure sidecars, including captured dependencies of synchronously invoked Tao callbacks. Sidecar authors do not construct wrappers; per-item memoization is optional optimization.
- Pure function sidecars receive immutable input snapshots; Tao owns reactive evaluation around the call and suppresses downstream propagation for equal outputs. They receive no subscription or mutation authority through those inputs.
- View-owned observations stop automatically on view disposal, with earlier manual cleanup available. Outside views, observations require an explicit lifetime owner or cleanup.
- Keep immutable snapshots, reactive readers and writable references distinct. Immutable values support `observe` with one immediate delivery and no retained subscription. `observe` on changing values delivers immediately and on change; `onChange` delivers only changes and never calls back for immutable values. Both use the same observation handle contract with harmless cleanup for immutable values.
- Sidecar contracts use deeply read-only types backed by runtime-owned immutable snapshots. Copy ordinary external lists/records at ingestion to prevent retained aliases from mutating published values; reuse already-owned snapshots without copying on every read. Entity and operation handles remain separate capabilities.
- Ordinary lists use ordered element value equality and ordinary records use field value equality. Entities and operation handles retain explicit identity, with reactive field/status updates. Sidecars publish replacements or use explicit reactive mutation APIs; enforce read-only ordinary snapshots where possible and distinguish read/write authority clearly in types and names.
- Expressions depend on their inputs, including callback reads. Re-evaluation propagates downstream only when the resulting value changes. Actions execute explicitly in response to events via `do`, not because their inputs change. See [Reactive Expressions](../Specification/Reactive%20Expressions.md).
- Inline pure function expressions use `Parameter -> expression`, with contextual parameter typing and inferred return types. Named pure functions remain usable in the same callback positions. See [Inline Functions](../Specification/Inline%20Functions.md).
- Filtering narrows the output element type when the compiler can prove the predicate's refinement. Ordinary boolean predicates remain valid without inferred narrowing.
- Named pure functions retain compiler-proven refinements automatically, including in compiled Tao exports across package boundaries. Opaque boolean-returning sidecars do not establish refinement proofs.
- Multi-statement inline pure functions use `Parameter -> { ... return Expression }`, with explicit return and the same restrictions as named pure functions. There is no implicit final-statement return.
- Use `==` and `!=` for equality and `is` for predicates. Infer return types by default and check explicit annotations.
- Type-only argument matching resolves exact type identities first, then forced compatible pairings. Ambiguity is an error. Implicit nominal admission goes up the type hierarchy. Construction from an ancestor to a descendant is explicit and checked.
- Constructors consume the full following expression. Group a constructed value before an operation on that value. Bare `Name(...)` calls a function. Signature-directed dot syntax disambiguates construction. Diagnose ambiguous expressions such as `Foo(Num -1)`.
- Use declared signature types and explicit typed literal construction. Named numeric domains use authored ordered operators. Invalid constant and dynamic arithmetic cause the same runtime failure.
- Publish pure TypeScript functions with named argument objects. Preserve distinct named Tao input types through generated checked constructors rather than accepting untyped primitive values in those fields. This supersedes the earlier primitive-scalar input baseline. The generated library must work from an ordinary TypeScript consumer, including headless use.

## Explicit deferrals

- Individual execution inspection, public actionStatus handles, richer action predicates and history/result selectors are post-MVP. [Advanced Action Execution](Advanced%20Action%20Execution.md) preserves prior directions and open decisions alongside progress, cancellation targeting, concurrency and retry. MVP direct aggregate `when ACTION` proceeds independently.
- Language-level action retry design and implementation are post-MVP. Preserve accepted constraints and unresolved alternatives in [Advanced Action Execution](Advanced%20Action%20Execution.md); ordinary action execution and inspection proceed independently. Provider-owned transaction/transport recovery remains subject to provider conformance.
- Defer execution-context, child-task spawning and managed event-registration API design until a concrete sidecar need requires them. Retain the requirement that generated sidecars have defined managed execution and failure behavior by default.
- Defer an HTTP convenience helper combining request, status checks and typed decoding until the explicit bridge is proven; keep it a library concern.
- Defer both the inclusion decision and implementation of `|>`. Reconsider its fit with Tao's design philosophy before accepting pipeline syntax.
- Signature-local declarations, contextual argument literals, parameter defaults, bounded generics, general structural capabilities and constant arithmetic diagnostics are post-MVP.
- Defer general improvements to Inspect, Render, and ToText unless needed to deliver an agreed decision. Failure-specific debug `Render` is now required by the accepted diagnostic contract.
