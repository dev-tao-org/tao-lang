These work items reflect [accepted design](Tao%20Language%20Design%20Decisions.md). The runtime changes and their verification are pending.

Its bounded contract design is settled; implementation has not been authorized. Deferred async helper, sidecar filename and developer-overlay details remain separate work.

## Unsequenced work by topic

- **Statement placement validation** — Replace location-specific statement parsing restrictions with permissive recognition and validator-owned owner/order/multiplicity checks. Preserve invalidly placed statements through AST generation and block invalid programs before compilation. Current grammar still restricts statements by block; this accepted architecture is not yet implemented. Prove misplaced statements parse and receive precise validation diagnostics. Coordinate shared grammar/AST/checker ownership before action policy syntax work.

- **Failure debug rendering** — Retain full rejected payloads separately from bounded issue lists. Expose inspection through failure-specific debug Render with useful context and expandable values; keep raw payloads out of default messages/logs and ordinary public payload access, while kinds/paths/constraints remain accessible. The accepted developer-overlay target owns exposure; its detailed design is deferred. Prove rendering, disclosure boundaries, complete retention and cleanup behavior; do not infer that pre-existing payload memory has no retention cost.
- **Managed sidecar execution** — First prove the ordinary generated sidecar boundary: synchronous throws, returned promise rejection, typed failure preservation, explicit domain translation and invalid results all have defined Tao handling. Protect outputs while permitting private construction. Defer child-work/context/event-registration API design until a concrete use case requires it, then establish its ownership and failure boundary before implementing that use case. Document and diagnose unmanaged detached work where feasible without claiming arbitrary foreign exceptions can always be caught.
- **Nominal identity and callback calls** — Prove same-declaration equal values compare equal through SDK operations across duplicate loaded compiled modules, and distinct nominal declarations remain distinct. Reject incompatible definitions of one nominal declaration rather than structurally admitting them. Preserve named argument objects in generated pure callback contracts. Exact identity/fingerprint representation is implementation design, not permission to add compatibility shims.
- **Sidecar authoring helper** — Generate concretely typed `sidecar.implement` from assigned declarations, plus checked `Type.from` factories raising typed Tao failures. Lowercase SDK names remain separate from uppercase authored declarations. Prove contextual parameter typing and rejection of missing/incompatible methods through compiled consumer fixtures; inspect editor completion before claiming that UX verified. Support sync or promise-returning actions, synchronous pure functions, and implicit standard boundary failures. Keep underlying helper machinery shared rather than duplicating runtime policy per module.
- **Same-module sidecar imports** — Support sidecars importing their owning Tao module's generated contracts and callable functions without initialization-cycle failures. Hide factory plumbing behind normal checked construction/encoding/decoding helpers. Prove a real external-boundary adapter through compiled Tao and TypeScript consumers before adding HTTP convenience helpers.
- **Nominal TypeScript boundary** — Preserve named Tao types in generated named-argument APIs with checked `Type.from` construction and immutable runtime nominal values. Preserve named outputs and explicit `encode()` extraction without silent coercion. Prove mismatched inputs fail type checking and declared value constraints are enforced in a real compiled TypeScript consumer. Equality compares declaration and payload, with stable identity across duplicate copies of the same compiled declaration; differing-version compatibility and exact identity representation remain open.
- **Pure function sidecars** — Generate immutable snapshot input contracts and compiler/runtime-owned reactive wrappers without requiring pure sidecar authors to construct them. Prove direct and synchronously invoked Tao callback-captured dependencies and equal-output propagation suppression before collection callbacks depend on this boundary. Exact wrapper/callback representation remains to be settled; per-item caching is optional optimization.
- **Pure callback lifetime** — Enforce evaluation-scoped callbacks in generated wrappers. Prove synchronous use succeeds and invocation after return or failure is rejected, without treating it as a subscription or silently attaching it to a later evaluation. Keep view/action callbacks separate.
- **View sidecar readers** — Replace raw view snapshot props with generated read-only reactive reader contracts; `state` adds writable authority. Exercise immutable and changing arguments, observation lifecycle and a compiled consumer. Coordinate this with snapshot ownership and observation contracts before implementing the migration.
- **Writable sidecar parameters** — Generate writable contracts from `Value state text` and check callers provide writable storage, including fields in explicitly owned draft state. Replace legacy `mutable` in the port; prove writes reach the caller's state and do not create a detached parameter copy. Preserve the ordinary view-reader contract when adding write authority.
- **Observation contracts** — Support immutable values, reactive readers and writable references with immediate-plus-change `observe` and change-only `onChange`. Prove immutable values retain no subscription, observe once, never deliver onChange, and allow harmless unobserve. Implement automatic cleanup of view-owned observations on disposal with earlier manual cleanup; outside views require an explicit lifetime owner or cleanup. Settle owner API shape before implementation and preserve distinct write authority.
- **Reactive expression dependencies** — Establish change-only propagation through direct and callback-mediated reads: unchanged expression outputs must not trigger downstream dependents. Track actual reads, refresh dependencies per evaluation, and prove inactive branch inputs do not trigger recomputation while branch switches read current values. Prove authored Tao and compiled library behavior, and that input changes do not re-execute actions. Implement accepted list/record value equality and entity/operation identity; settle scheduling details before implementing those aspects. Reuse the existing computed engine where it satisfies the contract.
- **Sidecar value ownership** — Implement deeply read-only generated types and runtime-owned immutable snapshots, copying ordinary external lists/records at ingestion and reusing already-owned snapshots. Prove nested mutation protection and that retained external aliases cannot silently modify published values through real sidecar/library consumers. Preserve explicit replacement/reactive mutation authority and separate entity/operation handles. Keep equality and snapshot work ahead of collection features that rely on them.
- **State and edits** — Implement detached drafts, opt-in persistence with explicit stable keys, and replacement semantics from [Local State and Data Drafts](../Specification/Local%20State%20and%20Data%20Drafts.md). Preserve recovery information when remote confirmation is unavailable and retain drafts after source deletion without implicit recreation. Sign-out clears all local app state, including persisted drafts and unsaved edits; prove later sign-in does not restore them.
- **Action execution** — Implement the accepted [action and result contracts](../Specification/Actions%20and%20Results.md), including passive inspection and failure presentation. Gate individual slices on acceptance of the syntax and contracts they require. Language-level retry, replay composition and automatic retry scheduling are post-MVP; see [Advanced Action Execution](Advanced%20Action%20Execution.md). Do not make them prerequisites for ordinary action/status/control slices.
- **Action activity and controls** — After per-view stable action ownership, implement aggregate `when ACTION` inspection and first-match render `pick ACTION` with an `otherwise` fallback. Prove pending takes precedence over a previous failed outcome when ordered first in `pick`, while `when` can display both. Public status handles, individual invocation inspection, history/result selectors and richer predicates are deferred in [Advanced Action Execution](Advanced%20Action%20Execution.md). Design the standard-library ActionButton against this reduced surface; its parameter contract remains open. Do not pull deferred invocation APIs into MVP as control prerequisites.
- **Disabled interaction — implemented** — Render modifiers carry inherited state through Tao views and sidecars. The UI Interactions journey covers inherited and direct disabled controls. The compiled TS Lib App consumer covers changing a boolean condition, attempted browser input and activation, a raw custom control, and programmatic work. Native device acceptance remains open. [Disabled interaction](../Specification/Actions%20and%20Results.md#disabled-interaction)
- **Typed calculations** — Implement the [accepted function, nominal-type and authored-operator rules](Tao%20Language%20Design%20Decisions.md#typed-calculations). Numeric representation, conversions and time types still require decisions before their implementation. Prove an authored Tao journey and compiled headless TypeScript consumption.
- **Inline functions** — Implement the accepted pure `Parameter -> expression` callback form, contextual parameter typing and inferred return types after shared function contracts exist. Prove authored Tao and compiled TypeScript consumption. Pipeline implementation is deferred together with its inclusion decision.
- **Filtering refinement** — After callback typing exists, prove that a type-test predicate narrows filtered elements and that ordinary boolean predicates do not introduce unsupported narrowing. Collection API spelling remains to be settled.
- **Exported refinements** — Preserve proven refinements when extracting inline predicates into named functions and compiling them across Tao package boundaries. Include a real compiled consumer proof; an opaque boolean-returning sidecar must not gain narrowing implicitly.
- **Inline block bodies** — Support explicit return, local calculations and branching under named pure-function restrictions. Prove rejection of mutations and action invocations, and no implicit final-statement return.
